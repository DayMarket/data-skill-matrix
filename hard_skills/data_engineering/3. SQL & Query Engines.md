# 3. SQL & Query Engines

Этот трек посвящён навыкам работы с SQL, включая написание сложных запросов, оптимизацию производительности и эффективное использование ClickHouse и Trino.

## DE1 (Junior)
- Пишет SELECT с фильтрацией, агрегацией и JOIN, CTE, window functions и аналитическими функциями.
- Понимает основные типы данных, первичные/внешние ключи и разницу OLTP vs OLAP.
- Создаёт таблицы и различает физический дизайн: ORDER BY/primary key/data-skipping indexes в ClickHouse и partitioning/table properties Iceberg через Trino.
- Понимает уровни изоляции транзакций и нормальные формы (1NF–3NF).
- Выполняет распределённые запросы через несколько источников, используя существующие каталоги Trino.

## DE2 (Middle)
- Создаёт MergeTree-таблицы, задаёт primary key, partition key, TTL и понимает процесс merges в ClickHouse.
- Использует Trino как слой федерации: соединяет данные из S3 + ClickHouse, делает CTAS или INSERT INTO в Iceberg.
- Использует существующие каталоги Trino, формулирует требования и валидирует подключение нового источника; rollout catalog configuration выполняется совместно с platform/infra owners.
- Читает system-таблицы и query logs для анализа «узких мест» принадлежащих команде запросов и таблиц (дисковое I/O, merges, пробки по памяти).

## DE3 (Middle+)
- Оптимизирует схемы (LowCardinality, Sparse columns), создаёт Materialized Views и Replacing/Collapsing/Aggregating MergeTree; настраивает TTL-политику и агрегирующие витрины в ClickHouse.
- По метрикам и логам диагностирует типовые проблемы принадлежащих команде query workloads, включая disk-bound merge, spill-to-disk и out-of-memory, и проверяет результат исправления.
- Понимает влияние типов данных и преобразований на производительность, избегает неявных кастов.
- Оптимизирует миграцию запросов с ClickHouse на Trino/Iceberg с учётом различий в синтаксисе и семантике.

## DE4 (Senior)
- Проектирует физические модели хранения под SLA запросов (hot/cold слои, сортировка, партиционирование).
- Анализирует cost-based plan Trino, использует session properties и Iceberg connector для оптимизации запросов.
- Ведёт диагностику неоднозначных и кросс-системных проблем query workloads, подтверждает root cause планами запросов и метриками и внедряет системные меры предотвращения.
- Отслеживает стоимость запросов и хранения данных; выявляет «дорогие» запросы и таблицы, предлагает и реализует оптимизации с измеримым снижением затрат.
- Проводит post-mortem анализ data-инцидентов и обучает команду оптимизации запросов.

### Антипаттерны DE4
- ❌ Создаю Materialized Views без анализа их влияния на производительность записи и дисковое пространство.
- ❌ Не документирую архитектурные решения по схемам хранения.
- ❌ Реактивно разбираюсь с проблемами query workloads вместо проактивного мониторинга.

## DE5 (Staff)
- Оценивает влияние новых версий ClickHouse/Trino на data workloads и контракты, совместно с platform owners формирует план миграции и валидирует совместимость.
- Формирует стратегию использования query engines в компании: стандарты, capacity planning, FinOps и governance каталога данных.
- Определяет критерии оценки и проводит R&D/PoC движков для решений, затрагивающих несколько доменов, документируя ROI, adoption и exit plan.
- Обучает продуктовые команды оптимизации затрат на хранение и вычисления и проводит архитектурные ревью.
- Определяет подход к автоматизированным миграциям схем и версионированию данных на уровне data-функции, включая compatibility, deprecation и rollback.
