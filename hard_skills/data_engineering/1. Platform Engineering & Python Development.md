# 1. Platform Engineering & Python Development

Этот трек посвящён навыкам разработки платформенных инструментов, внутренних библиотек и автоматизаций — всё, что делает работу data-платформы надёжной и масштабируемой.

## DE1 (Junior)
- Пишет скрипты на Python для задач обработки данных (парсинг, трансформации, загрузки).
- Использует git: ветвление, коммиты, pull requests.
- Читает и ориентируется в существующем коде проекта, может внести локальные правки.
- Использует базовые средства отладки (breakpoints, logging, print-debugging).
- Оформляет код по style-guide проекта и пишет понятные описания к PR.

## DE2 (Middle)
- Разрабатывает многомодульные Python-приложения (CLI-инструменты, batch-джобы) с применением популярных библиотек.
- Пишет модульные тесты для критического функционала.
- Проходит код-ревью и оперативно правит замечания.
- Собирает Docker-образы для своих приложений и Spark-джоб.
- Запускает и диагностирует собственные data workloads в Kubernetes: читает Pod events и logs, настраивает requests/limits, probes, ConfigMap и Secret по утверждённым шаблонам; cluster-level изменения согласует с platform/infra owners.
- Понимает как работает CI/CD пайплайн проекта (Drone/GitHub Actions) и может внести изменения в конфигурацию.

## DE3 (Middle+)
- Проводит код-ревью коллег, аргументируя решения ссылками на стандарты и лучшие практики.
- Пишет модульные и интеграционные тесты, обеспечивая покрытие критических путей.
- Настраивает и поддерживает CI-пайплайны: линтинг, тесты, сборка артефактов, деплой.
- Создаёт переиспользуемые пакеты и библиотеки для команды (например, custom Airflow Operators/Hooks).

## DE4 (Senior)
- Разрабатывает внутренние платформенные инструменты (CLI для автоматизации, генераторы конфигов, фреймворки обработки данных).
- Настраивает мониторинг, логирование и алерты (Prometheus, Grafana, Grafana OnCall) для приложений и пайплайнов.
- Управляет релизным циклом: версионирование, changelog, rollback-план.
- Внедряет и развивает стандарты код-ревью, CI/CD и release management для принадлежащих команде сервисов и добивается их применения в связанных командах.

### Антипаттерны DE4
- ❌ Создаю «одноразовые» решения вместо переиспользуемых инструментов.
- ❌ Не документирую архитектурные решения и API внутренних инструментов.
- ❌ Внедряю новые технологии без оценки операционной сложности и затрат на поддержку.

## DE5 (Staff)
- Проектирует целевую архитектуру кросс-командных платформенных сервисов, определяет модули, контракты и путь эволюции.
- Формирует технический roadmap платформы и ведёт RFC-процессы.
- Определяет критерии выбора новых технологий и проводит PoC для решений уровня платформы, фиксируя trade-offs, rollout и exit criteria.
- Определяет и согласует стандарты разработки, качества и безопасности кода для data-функции.
- Руководит разработкой и поддержкой внутренних библиотек и SDK (airflow-commons, data-platform-automation).
- Задаёт стандарты профилирования и performance budgets для платформенных сервисов, отслеживает эффект их применения и устраняет системные bottleneck'и.
